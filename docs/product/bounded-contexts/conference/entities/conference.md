# Entity: Conference

> **Wave 1 reality check.** `ConferenceStatus` ships all eight states, but the class ships **one**
> mutator (`publishCfp()`). Rows that describe the rest of the lifecycle are specifications, so they
> carry `⏳ Planned` and are phrased in the future tense — present tense would claim the code ships.
> Convention: [Traceability](../../../guidelines/traceability.md).

## 📋 Definition & Context

* **Description:** A Call for Papers (CfP) conference organized by a user. Owns the CfP submission window and the conference lifecycle state machine.
* **Aggregate Root:** ✅ Yes — consistency boundary over `CfpConfig` and the status state machine (INV-001).
* **Implementation:** `packages/modules/conference/src/domain/conference.ts`
* **Persistence schema:** `conferences` table — `packages/shared/database/src/schema.ts:16-39`
* **Primary Key / Identifier:** `ConferenceId` (UUIDv4 value object; minted by `ConferenceId.generate()`)
* **Owner Team:** Core Conference Team
* **Domain Context:** Conference Bounded Context (ADR-009)
* **Built scope:** creation + CfP opening. Review, selection, scheduling, publishing, completion and cancellation are specified, not implemented.

## 🧱 DDD Structure

### Aggregate Composition

Mirrors `ConferenceData` (`conference.ts:16-26`) — every persisted member is a value object except the two timestamps.

```
Conference (Aggregate Root)
├── id: ConferenceId                    // uuid, generated by ConferenceId.generate()
├── name: ConferenceName                // 3–100 chars after trim (BR-002)
├── description: ConferenceDescription  // optional, default '' (schema default)
├── slug: ConferenceSlug                // url-safe, unique (BR-003 / INV-003)
├── status: ConferenceStatus            // 8 states + TRANSITIONS table (INV-001)
├── organizerId: OrganizerId            // tenant key for BR-004
├── cfpConfig: CfpConfig                // embedded configuration (see below)
├── createdAt: Date                     // not a VO, deliberately
└── updatedAt: Date                     // refreshed by publishCfp() and by repository save()

CfpConfig (embedded, domain/value-objects/cfp-config.ts)
├── startDate: CfpStartDate             // today or future, ≤ 365 days ahead (BR-001)
├── endDate: CfpEndDate                 // valid date (BR-001)
├── maxSubmissions?: MaxSubmissions     // positive integer
├── requiresApproval: RequiresApproval  // defaults to true
└── status: CfpStatus                   // ACTIVE | CLOSED | ARCHIVED
```

`⏳ Planned — no code exists for either of these, and neither has a class today:`

* `Sessions` (child entities) — required by `INV-004` / `INV-005`; there is **no** `Session` entity in `domain/`.
* `ConferenceValidationService` (domain service) — no `domain-services/` directory exists; validation lives in the value objects.

## 🔍 State Definitions

All eight values exist in `ConferenceStatus` (`domain/value-objects/conference-status.ts:4-11`), and
`TRANSITIONS` (:15-22) already declares the full graph. Reachability is the part that is partial.

| State | Meaning | Reachable today |
|-------|---------|-----------------|
| `DRAFT` | Created, CfP not open yet | ✅ via `create()` |
| `CFP_OPEN` | Accepting submissions within the `CfpConfig` window | ✅ via `publishCfp()` |
| `CFP_CLOSED` | Window shut; entries frozen pending review | ❌ no mutator |
| `REVIEWING` | Organizers scoring entries | ❌ no mutator, no `Session` entity |
| `SCHEDULED` | Accepted sessions chosen, not public yet | ❌ no mutator |
| `PUBLISHED` | Public agenda available | ❌ no mutator |
| `COMPLETED` | Conference finished, terminal | ❌ no mutator |
| `DELETED` | Soft delete, terminal; excluded from the free-tier count | ❌ no mutator (the `ne(status,'DELETED')` filter in the repository is built) |

**Consistency:** every state above appears in exactly one diagram and one matrix row per direction, and
every arrow in both diagrams appears in the matrix (SKILL §Mermaid consistency 1-5).

| Method | Purpose | Preconditions | Effects | Status |

| `protected recordEvent(event)` | Event recording hook for the aggregate | Subclass-visible only | Appends to `_domainEvents` | ✅ Built |
| `closeCfp(reason)` | Will close the submission window | `CFP_OPEN` | Will emit `CfpClosedEvent` | ⏳ Planned |
| `startReview()` | Will open the review phase | `CFP_CLOSED` | Will emit `ReviewStartedEvent` | ⏳ Planned |
| `completeSelection()` | Will finalize acceptances | `REVIEWING`; all sessions scored (INV-004) | Will emit `SelectionCompletedEvent` | ⏳ Planned |
| `publishSchedule()` | Will make the agenda public | `SCHEDULED`; all sessions assigned (INV-005) | Will emit `SchedulePublishedEvent` | ⏳ Planned |

| `cancel(reason)` | Will soft-delete the conference | `DRAFT` or `CFP_OPEN` | Will emit `ConferenceCancelledEvent` | ⏳ Planned |

## 🛠️ Repository Interface

Transcribed from the persistence port in `domain/` — do not "improve" it here.

```typescript
// packages/modules/conference/src/domain/conference-repository.interface.ts:17-23
export interface ConferenceRepository {
  findById(id: ConferenceId): Promise<Conference | null>;
  findBySlug(slug: ConferenceSlug): Promise<Conference | null>;
  /** Counts non-DELETED conferences for an organizer (BR-004). */
  countActiveByOrganizerId(organizerId: OrganizerId): Promise<number>;
  save(conference: Conference, tx?: TransactionClient): Promise<void>;
}
```

> `save()`'s optional `tx` is not decoration: when `CreateConferenceHandler` passes it
> (`create-conference.handler.ts:87-89`), the aggregate write and the Outbox insert join one
> transaction, which is what makes ADR-017's Outbox atomic. Documenting `save(conference)` alone hides
> the guarantee.
>
> `delete(id)`, `findByOrganizerId()` and `findByStatus()` are **not** on the port. `DELETED` is reached
> through a `cancel()` mutator that is `⏳ Planned`, and organizer/status listings are not implemented —
> the repository exposes an index on each column (`schema.ts:37-38`) but no query for them.
